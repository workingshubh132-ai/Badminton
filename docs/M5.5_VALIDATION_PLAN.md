# M5.5: Real-World CV Validation — Implementation Plan

## Objective

**Validate the existing M5 badminton computer-vision pipeline on REAL badminton footage before building higher-level intelligence (M6+).**

This milestone is a validation gate. It does not build new features — it validates whether M5's perception layer works reliably enough on real footage to support downstream analysis.

## What M5.5 Delivers

✓ Dataset ingestion system with proper licensing metadata  
✓ Video clipping utility for creating evaluation clips  
✓ Web annotation interface for ground-truth labeling  
✓ Automatic evaluation runner (M5 pipeline + accuracy metrics)  
✓ Visual overlay generation (predictions vs ground truth)  
✓ Comprehensive evaluation report with component readiness classifications  
✓ Decision-gate recommendation (A-F) for next steps  

## What M5.5 Does NOT Build

✗ Shuttle/racket tracking  
✗ Shot classification  
✗ Rally reconstruction  
✗ Tactical analysis  
✗ Game-state reasoning  
✗ Decision intelligence  
✗ AI coaching conclusions  

## Workflow

```
Real Video (licensed) → Ingest (metadata + storage)
                      ↓
            Create Clips (10-30s segments)
                      ↓
        Annotate Clips (ground truth)
                      ↓
    Run M5 Pipeline (court, detection, tracking, quality)
                      ↓
    Calculate Accuracy Metrics (vs ground truth)
                      ↓
        Generate Evaluation Report
                      ↓
        Classify Components (4 readiness levels)
                      ↓
    Recommend Next Step (decision gate A-F)
```

## Detailed Deliverables

### 1. Dataset Management (`cv-service/eval/dataset.py`)

**Purpose**: Centralized management of videos, clips, annotations, and evaluations.

**Key Classes**:
- `DatasetManager` — main interface
  - `ingest_video()` — import video with licensing metadata
  - `create_clip()` — create evaluation clip from source video
  - `get_annotation_path()` — locate annotation file
  - `load_annotation()` / `save_annotation()` — annotation persistence
  - `load_evaluation()` / `save_evaluation()` — evaluation result persistence
  - `list_unannotated_clips()` — find clips needing annotation
  - `list_unevaluated_clips()` — find clips waiting for M5 evaluation

**Storage**:
```
cv-service/eval/datasets/
├── inventory.json              # Central registry
├── videos/                     # Source videos (copies)
├── clips/                      # Evaluation clips
├── annotations/                # Ground-truth JSON
├── evaluations/                # M5 results JSON
└── overlays/                   # Visual comparisons (MP4/JPG)
```

### 2. Schemas (`cv-service/eval/schemas.py`)

Pydantic models for:
- **VideoMetadata** — source video info (license, source URL, camera, FPS, codec, etc.)
- **ClipMetadata** — clip info (source video ID, start/end, visibility, annotation status)
- **FrameAnnotation** — ground truth for one frame (quality, court corners, player bboxes)
- **AnnotationMetadata** — complete annotation set for a clip (v1 schema)
- **CourtAccuracy** — court calibration metrics (corner error, IoU, confidence)
- **DetectionAccuracy** — player detection metrics (precision, recall, TP/FP/FN)
- **TrackingAccuracy** — tracking metrics (track length, gaps, switches)
- **QualityAssessmentAccuracy** — quality classification accuracy
- **ClipEvaluationResult** — complete evaluation for one clip
- **ComponentReadiness** — classification for one M5 component
- **EvaluationReport** — aggregate report with decision gate

### 3. Ingestion CLI (`cv-service/eval/ingest.py`)

**Usage**:
```bash
python -m eval ingest ~/badminton.mp4 \
  --license licensed \
  --source-url "https://example.com/video" \
  --camera "sideline" \
  --players "Alice" "Bob" \
  --notes "Good lighting, both players visible"
```

**Outputs**:
- Generates unique `video_id` (timestamp-based)
- Copies video to `datasets/videos/{video_id}.mp4`
- Extracts metadata via ffprobe (duration, resolution, FPS, codec)
- Stores metadata in `inventory.json`
- Prints confirmation with metadata

### 4. Clipping Utility (`cv-service/eval/clipping.py`)

**Usage**:
```bash
python -m eval clipping video_20260906_120000_badminton \
  --start 10.0 \
  --end 25.0 \
  --camera "sideline" \
  --court-visible \
  --players 2
```

**Outputs**:
- Creates clip via ffmpeg from source video bytes
- Generates unique `clip_id`
- Stores in `datasets/clips/{clip_id}.mp4`
- Updates `inventory.json`

**Target Dataset**:
- 5–10 clips total
- 10–30 seconds each
- Different source videos
- Full court visible in each
- 2 players visible (singles badminton)
- Variety of player positions
- Different lighting/camera angles

### 5. Annotation Web Interface (`cv-service/eval/annotation_server.py`)

**Purpose**: Minimal but usable interface for labeling ground truth.

**Technology**: Flask (lightweight)

**Features**:
- Display video frames as JPG thumbnails
- Interactive canvas for marking court corners
- Bounding box drawing for players
- Player identity assignment (athlete/opponent/unknown)
- Frame quality marking (good/acceptable/poor/unusable)
- Frame-by-frame navigation
- Save/resume functionality

**URL Structure**:
```
GET  /                          # List clips needing annotation
GET  /annotate?clip_id=...      # Annotation interface
GET  /api/clip/{id}/frames      # Get frames as dataURLs
POST /api/clip/{id}/annotation  # Save annotation
```

**Output Format**: JSON (`v1` schema) with normalized [0,1] coordinates

### 6. Evaluation Runner (`cv-service/eval/evaluate_real.py`)

**Purpose**: Run M5 pipeline against annotated clips and compute accuracy metrics.

**Class**: `RealFootageEvaluator`
- `evaluate_clip(clip_id)` — main evaluation function
  - Loads annotation (ground truth)
  - Runs M5 pipeline via `run_analysis()`
  - Computes court accuracy (corner errors, IoU)
  - Computes detection accuracy (precision, recall)
  - Computes tracking accuracy (track length, gaps, switches)
  - Computes quality accuracy (classification vs annotated)
  - Identifies failures
  - Returns `ClipEvaluationResult`

**Usage**:
```bash
python -m eval evaluate clip_20260906_120015_video_001_10-25 \
  --sampling-fps 2.0
```

**Metrics Computed**:
- **Court**:
  - Mean/max corner error in pixels (Euclidean distance)
  - Quad IoU (vs annotated court)
  - Homography success
  - Detection status + confidence
- **Detection**:
  - Precision (TP / (TP + FP))
  - Recall (TP / (TP + FN))
  - IoU per detection
  - Confusion matrix (GT vs predicted)
- **Tracking**:
  - Mean track length (frames)
  - Tracking gaps (count + max duration)
  - Identity switches
  - Track fragmentation
- **Quality**:
  - Frame-level classification accuracy vs annotated quality
  - Per-class precision/recall

### 7. Visual Overlays (`cv-service/eval/overlay.py`)

**Purpose**: Generate comparison images/videos for manual inspection.

**Functions**:
- `generate_overlay_image(clip_id, frame_index)` — single frame with ground truth drawn
- `generate_overlay_video(clip_id)` — full clip with ground truth overlay

**Visualization**:
- Green: ground-truth court corners + player boxes
- Labels: player identity + frame quality
- Per-frame timestamp

**Output**:
- Images: `datasets/overlays/{clip_id}_frame_NNN.jpg`
- Videos: `datasets/overlays/{clip_id}_overlay.mp4`

### 8. Report Generator (`cv-service/eval/report_generator.py`)

**Class**: `ReportGenerator`

**Functions**:
- `generate_report()` — compute aggregate metrics across all evaluated clips
- `render_markdown()` — format report as markdown
- `generate_and_save()` — write report files

**Aggregation Methods**:
- `_aggregate_court_metrics()` — mean/median/max errors, success rate, IOUs
- `_aggregate_detection_metrics()` — precision, recall, FP/FN counts
- `_aggregate_tracking_metrics()` — mean track length, gap counts, switch counts
- `_aggregate_quality_metrics()` — classification accuracy

**Classification Methods** (one per component):
- `_classify_court()` → ComponentStatus (PRODUCTION_READY | VALIDATION_READY | NEEDS_IMPROVEMENT | UNRELIABLE)
- `_classify_detection()` → ComponentStatus
- `_classify_tracking()` → ComponentStatus
- `_classify_quality()` → ComponentStatus

**Decision Gate Method**:
- `_determine_decision_gate()` → (letter A-F, rationale string)

**Output**:
```
cv-service/eval/datasets/
├── M5.5_EVALUATION_REPORT.md     # Human-readable
└── M5.5_EVALUATION_REPORT.json   # Machine-readable
```

## Component Readiness Classifications

Each M5 component receives exactly **ONE** of four statuses:

| Status | Meaning |
|--------|---------|
| **PRODUCTION_READY** | Reliable on real footage; ready for downstream use (M6+) |
| **VALIDATION_READY** | Promising; needs monitoring; acceptable for limited use |
| **NEEDS_IMPROVEMENT** | Works but has identifiable issues; not ready for production |
| **UNRELIABLE** | Cannot safely support downstream intelligence |

## Decision Gate (A-F)

At the end of evaluation, recommend **exactly ONE** next step:

| Gate | Recommendation | Rationale |
|------|---|---|
| **A** | Proceed to M6 | All components PRODUCTION_READY or VALIDATION_READY |
| **B** | Improve court detection | Court calibration UNRELIABLE; foundational for all else |
| **C** | Improve player detection | Low precision/recall; cannot track what isn't detected |
| **D** | Improve tracking | Fragmented tracks; need better IoU matching/gap bridging |
| **E** | Improve quality assessment | Quality classification accuracy below threshold |
| **F** | Redesign perception architecture | Multiple components UNRELIABLE; systemic issues |

**Important**: Never choose A merely because tests pass. **A requires evidence-based confidence on real footage.**

## Notes on Architecture

**Preservation of separation**:
```
PERCEPTION (M5, validated by M5.5)
    ↓
EVIDENCE (ground-truth annotations + M5 measurements)
    ↓
INTERPRETATION (future: rally reconstruction)
    ↓
COACHING (future: AI coach output)
```

M5.5 produces **perception-level evidence only**. It does not create coaching conclusions or interpretation. The output is raw measurement: "court detection succeeded with X corner error" and "precision/recall for detection were Y/Z".

**Important limitation accepted in M5.5**:
- Real badminton footage accuracy is **not fully validated** — only synthetic-fixture geometry has been proven correct (M5 final state)
- Acceptance thresholds for production readiness are **provisional**
- This is intentional: M5.5 is a validation gate that may recommend "redesign perception architecture" (gate F) based on real evidence
