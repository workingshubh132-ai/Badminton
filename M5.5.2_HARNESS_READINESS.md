# M5.5.2 — Real-World Validation Harness: Readiness

_Milestone: validation harness only. No M6, no shuttle or shot work, no UI surfacing,
no threshold tuning, and no real-world validation claimed._

## Headline

A real badminton video can now go `incoming → ingest → clip → annotation → evaluation →
report` with no code changes. Before this slice it could not: the pipeline had never been
run end to end, and **six separate breakages** sat in the path a real video would take.
Each was found by driving the flow, not by reading it.

The harness is ready. The evidence is not, and the report now refuses to pretend
otherwise.

---

## 1. What is now ready

### The pipeline actually runs

Six defects, every one of which would have blocked the first real video:

| # | Defect | Effect if unfixed |
|---|---|---|
| 1 | `model_dump_json(default=str)` — Pydantic v1 call on v2 models | Ingest died on step one; **nothing** could enter the dataset |
| 2 | `from flask import render_string` — not a Flask export | Annotation server could not start at all |
| 3 | `m5_result.calibration.homography_matrix` — field is `homography` | Evaluation crashed after running the full M5 pipeline |
| 4 | Annotation server hardcoded `players: []` | **Drawn boxes were silently discarded.** No player ground truth could ever be produced, so detection and participant scoring had nothing to score against |
| 5 | Report renderer called `.get()` on Pydantic models, and `%`-formatted possible `"?"` strings | Report generation crashed once any clip was evaluated |
| 6 | `source_video_id` was set to the clip id | Every result mis-attributed to its own clip, breaking provenance |

Defect 4 is the serious one. The annotation UI let you draw boxes and drew them on the
canvas, so it looked like it worked; the save path threw them away. Court corners and
quality saved fine, which is why it went unnoticed.

A seventh issue was a lie rather than a crash: `python -m eval list` computed
`evaluated = clips − unevaluated`, reporting clips that were never annotated as
**evaluated**. A validation harness that overstates its own readiness is worse than one
that crashes. It now counts evaluation files directly and reports annotated, awaiting
annotation, evaluated and awaiting evaluation separately.

### Annotation captures what evaluation needs

Court corners, per-person bounding boxes, quality label, identity
(athlete/opponent/unknown) — and now participant status
(participant/non-participant/unknown) as a **separate axis**. Annotators are told to box
*everyone visible* including spectators and officials, because bystanders are exactly
what participant classification must be scored against. Boxes are colour-coded by
participant status, support undo/clear, and normalise against the real canvas size rather
than a hardcoded 1280×720.

### Participant classification can be scored

Ground truth is matched to M5 output spatially (best-IoU at the nearest sampled
timestamp, 0.3 IoU / 0.75 s tolerance), yielding precision, recall, F1, plus two metrics
the brief specifically asked for:

- **False-participant rate** — of annotated bystanders, the fraction M5 promoted to
  players. Tracked separately from precision because a spectator entering player analysis
  corrupts everything downstream, and >10% forces UNRELIABLE on its own.
- **Unresolved rate** — of resolvable people, the fraction M5 left UNKNOWN. High values
  mean safe but not yet useful.

Two scoring decisions worth stating, because they are judgement calls:

- People the **annotator** left UNKNOWN are excluded from precision/recall entirely. A
  human who could not tell is not ground truth for either answer.
- **M5's** UNKNOWNs count as neither true nor false positives; they surface only in
  unresolved rate. Scoring "I don't know" as a wrong answer would rank a classifier that
  guesses above one that admits uncertainty — the opposite of what M5.5.1 was built for.

### Synthetic and real-world evidence cannot be merged

This is enforced structurally, not by convention:

- `validation_kind` is a property of the **source video's provenance**, set at ingest,
  never of the evaluation run.
- It defaults to `SYNTHETIC`. Real-world status requires an explicit `--real-footage`
  assertion, so a forgotten flag **under-claims**; footage is never silently promoted.
- Component readiness and the decision gate are computed from real-world clips **only**.
  Synthetic results cannot move them.
- With no real-world clips the gate is `NO_REAL_WORLD_EVIDENCE` — a state from which
  gate A is unreachable — and every component is classified UNRELIABLE with the reasoning
  "never been evaluated against real badminton footage… an absence of evidence, not a
  measured failure".
- The report opens with a banner saying so, and per-clip results are rendered in two
  separately captioned tables.

### Dataset manifest

`python -m eval manifest` writes `DATASET_MANIFEST.md`/`.json` covering provenance,
licence status, licence terms URL, who verified it, source, resolution, FPS, duration,
codec, camera type, burned-in overlays, and known match format.

Licence status now includes `LICENSE_REVIEW_REQUIRED` and **it is the default** — a
licence nobody has read is not a permissive one. `licensed`/`reference` require a human to
have read the terms, recorded via `--license-verified-by`. Blank fields render as `—`,
explicitly meaning "never recorded", not "absent".

`has_burned_in_overlays` exists because of what the GitHub investigation found: two of the
six clips had pose skeletons, drawn court lines and mini-maps rendered into the pixels.
Footage like that corrupts court evaluation at any licence status, so it is now a recorded
property rather than something to rediscover.

### Tests

22 new tests in `tests/test_validation_harness.py`, covering the full workflow on the
synthetic fixture, the participant metric maths on constructed inputs, the synthetic/real
separation, and the manifest. **83 Python tests, 66 TypeScript tests, `tsc` and `eslint`
clean.**

## 2. What evidence is still missing

**Everything that matters.** The harness is machinery; it has measured nothing real.

- **Zero real-world clips have been evaluated.** Every component is UNRELIABLE for absence
  of evidence.
- M5's accuracy on real badminton — court calibration, detection, tracking, quality — is
  entirely unmeasured. The synthetic fixture contains a rendered court and a moving
  rectangle, no humans.
- **M5.5.1's participant classifier has never seen a real spectator.** Its thresholds
  (1.5 m play-area margin, 0.7 inside-ratio, 0.25 coverage, 1.0 m displacement) are
  reasoned, not fitted. Per instruction they remain untuned.
- Detection scoring is still **count-based, not IoU-matched** (`_evaluate_detection` matches
  totals per clip). Participant scoring does match spatially; detection does not. This
  overstates precision/recall when counts coincide but boxes do not, and should be fixed
  before detection numbers are trusted. Not fixed here to keep this slice to the harness.
- Tracking metrics are thin: `identity_consistency` and `identity_switches` are not
  computed against ground truth.
- The annotation UI annotates **one frame per clip**. Multi-frame annotation is the format,
  but the UI writes a single frame, so tracking-over-time cannot yet be scored properly.

## 3. Exact minimum real footage required to unlock M6

Gate A requires every component to reach PRODUCTION_READY or VALIDATION_READY on
real-world evidence. Working back from the thresholds in `report_generator.py`:

### Quantity

| Requirement | Minimum | Why |
|---|---|---|
| Distinct source videos | **3** | One venue cannot show whether results generalise |
| Evaluation clips | **5–8** | Court success rate is scored per clip; 5 is the fewest that makes a ≥90% rate meaningful |
| Clip length | **15–30 s each** | Long enough to contain a full rally and ≥30-frame tracks |
| Total footage | **2–5 minutes** | Follows from the above |
| Annotated frames | **≥150** (≈2 fps across the clips) | Quality accuracy ≥85% needs enough frames to separate from chance |
| Annotated people | **≥100 person-instances** | Detection precision ≥90% / recall ≥85% |
| Annotated **bystanders** | **≥30 person-instances** | The binding constraint — see below |

The bystander count is the one most likely to be missed. The false-participant threshold
is 10%; with fewer than ~30 annotated bystanders you cannot distinguish 10% from 0%, so a
clip with two players and nobody else **cannot validate the participant classifier at
all**. Footage must contain people who are near the court but not playing.

### Quality

- Full court visible, all four corners, in every clip
- **No burned-in graphics** — no pose overlays, drawn lines, mini-maps or scoreboards
- At least 2 distinct camera positions across the set, and ≥2 lighting conditions
- ≥720p, ≥24 fps, continuous within each clip (no cuts mid-clip)
- Singles preferred; include ≥1 doubles clip to exercise the 4-participant path

### Provenance

- Licence read by a human and recorded (`--license-verified-by`), status `licensed` or
  `reference`, not `LICENSE_REVIEW_REQUIRED`
- Ingested with `--real-footage`, or it will be scored as synthetic and excluded
- Provenance and overlay status recorded in the manifest

### The practical route

A phone on a tripod at a club court, filming two players with others waiting courtside,
produces all of the above in a single session — including the bystanders the participant
classifier needs, and with unambiguous ownership. It also matches the deployment domain
far better than broadcast: fixed elevated telephoto with on-screen graphics is not what
this product will actually be pointed at.

The quarantined broadcast footage remains untouched in
`dataset_v1/quarantine_license_review/`, outside the candidate path, and was neither
ingested nor modified.

### Command sequence once footage exists

```bash
cd cv-service
python -m eval ingest /path/to/match.mp4 \
  --real-footage --license licensed --license-verified-by "<name>" \
  --license-terms-url "<url>" --provenance "Recorded at <club>, <date>, own footage" \
  --camera "sideline tripod" --no-overlays --match-format singles
python -m eval clipping <video_id> --start 40 --end 60 --court-visible --players 2
python -m eval annotate-server          # box everyone, including bystanders
python -m eval evaluate <clip_id>
python -m eval report                   # readiness + decision gate, real-world only
python -m eval manifest
```

## 4. Status

**Ready**: harness runs end to end; participant ground truth and scoring exist; synthetic
and real-world evidence are structurally separated; manifest records provenance and
licence.

**Not ready**: no real-world evidence of any kind. Gate is `NO_REAL_WORLD_EVIDENCE`. M6
remains blocked, and no component readiness is claimed.

M5 algorithms were not modified. No participant or format fields were surfaced in the UI.
No thresholds were tuned. No footage was downloaded.
