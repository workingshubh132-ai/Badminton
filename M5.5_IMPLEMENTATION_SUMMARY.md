## What is M5.5?

M5.5 is a **validation gate** for the M5 computer-vision pipeline. It provides infrastructure to evaluate whether M5's perception layer (court detection, player detection/tracking, quality assessment) works reliably on **real badminton footage** before building higher-level intelligence (M6 shot detection, M7+ analysis).

**Critical point**: M5.5 does not build new features. It validates existing ones using measured evidence on real footage.

## How M5.5 Works

### 1. Video Ingestion

```bash
python -m eval ingest ~/badminton.mp4 \
  --license licensed \
  --source-url "https://..." \
  --camera "sideline"
```

**Output**: Unique `video_id`, video copied to storage, metadata stored

### 2. Clip Creation

```bash
python -m eval clipping video_001 \
  --start 10 --end 25 --court-visible --players 2
```

**Output**: Evaluation clip (10-30s segment) with metadata

### 3. Annotation (Web UI)

```bash
python -m eval annotate-server --port 5000
# Visit http://localhost:5000
```

**Annotator marks**:
- Court corners (4 points)
- Player bounding boxes
- Player identity (athlete/opponent/unknown)
- Frame quality (good/acceptable/poor/unusable)

**Output**: `annotations/{clip_id}.json` with normalized [0,1] coordinates

### 4. M5 Evaluation

```bash
python -m eval evaluate clip_001_10-25 --sampling-fps 2.0
```

**Pipeline**:
1. Load ground-truth annotation
2. Run M5 pipeline on clip
3. Calculate accuracy metrics:
   - **Court**: corner error (px), IoU vs annotated court
   - **Detection**: precision, recall, F1
   - **Tracking**: track continuity, gaps, identity switches
   - **Quality**: classification accuracy
4. Record failures
5. Save evaluation result to `evaluations/{clip_id}.json`

### 5. Report Generation

```bash
python -m eval report
```

**Output**: `M5.5_EVALUATION_REPORT.md` + `.json` containing:
- Per-clip metrics
- Aggregate metrics across all clips
- Component readiness classifications
- Failure analysis
- Decision-gate recommendation (A-F)

---

## Component Readiness Classifications

Each M5 component receives one of four statuses:

| Status | Meaning |
|--------|---------|
| **PRODUCTION_READY** | Reliable on real footage, ready for M6 |
| **VALIDATION_READY** | Good, but needs monitoring |
| **NEEDS_IMPROVEMENT** | Works but has known issues |
| **UNRELIABLE** | Cannot safely support downstream analysis |

---

## Decision Gate (A-F)

The evaluation report recommends exactly one next step:

| Gate | Recommendation |
|------|---|
| **A** | Proceed to M6 (all components PRODUCTION_READY or VALIDATION_READY) |
| **B** | Improve court detection (is UNRELIABLE) |
| **C** | Improve player detection (low precision/recall) |
| **D** | Improve tracking (fragmented tracks) |
| **E** | Improve quality assessment (accuracy issues) |
| **F** | Redesign perception architecture (multiple critical failures) |

**Key principle**: Gate A is only recommended when evidence-based confidence exists. Not when tests pass, but when real footage validates the pipeline.

```json
{
  "version": "1.0",
  "clip_id": "clip_...",
  "created_at": "2026-09-06T...",
  "annotator": "alice",
  "frames": [
    {
      "frame_index": 0,
      "timestamp_seconds": 0.0,
      "quality": "good",
      "court_corners": {
        "top_left": [0.15, 0.10],
        "top_right": [0.85, 0.10],
        "bottom_right": [0.90, 0.90],
        "bottom_left": [0.10, 0.90]
      },
      "players": [
        {
          "identity": "athlete",
          "bbox": {"x1": 0.20, "y1": 0.30, "x2": 0.35, "y2": 0.50},
          "confidence": 0.95
        }
      ]
    }
  ]
}
```

**Coordinates**: Normalized to [0, 1] where (0,0) is top-left, (1,1) is bottom-right.

## Licensing Requirement

**Every external video must store proper licensing metadata:**

```python
python -m eval ingest badminton.mp4 \
  --license licensed      # We have permission to use/retain
  --source-url "https://..."
  --source-description "From XYZ club"
```

**License types**:
- **LICENSED** = Explicit permission to download, modify, analyze, retain
- **REFERENCE** = Research/elite footage, reference only, not distributable

This metadata is stored and queryable, ensuring no silent misuse of copyrighted footage.

## Metrics Computed

### Court Calibration

- Mean corner error (pixels, Euclidean distance)
- Max corner error
- Quad IoU (vs ground-truth court quadrilateral)
- Confidence level
- Homography success (true/false)
- Success rate across clips

**Thresholds for PRODUCTION_READY**:
- Success rate ≥ 90%
- Mean error < 10px
- Mean IoU > 0.95

### Player Detection

- True Positives, False Positives, False Negatives
- Precision = TP / (TP + FP)
- Recall = TP / (TP + FN)
- Per-detection IoU
- Confusion matrix (GT vs predicted)

**Thresholds for PRODUCTION_READY**:
- Precision ≥ 90%
- Recall ≥ 85%

### Player Tracking

- Mean track length (frames)
- Tracking gaps (count + max duration)
- Identity switches
- Track fragmentation

**Thresholds for PRODUCTION_READY**:
- Mean track length ≥ 30 frames
- No gaps or switches

### Quality Assessment

- Frame-level classification accuracy
- Per-class precision/recall
- Confusion matrix

**Thresholds for PRODUCTION_READY**:
- Accuracy ≥ 85%

## Example Workflow (5-Clip Validation)

```bash
# 1. Ingest 5 videos (with licenses!)
python -m eval ingest match1.mp4 --license licensed --source-url "..." --camera "sideline"
python -m eval ingest match2.mp4 --license licensed --source-url "..." --camera "overhead"
# ... x3 more

# 2. Create 5 evaluation clips (different angles, lighting, positions)
python -m eval clipping video_001 --start 10 --end 25 --court-visible --players 2
python -m eval clipping video_002 --start 15 --end 30 --court-visible --players 2
# ... x3 more

# 3. Annotate all clips (web UI, ~5-10 min per clip)
python -m eval annotate-server --port 5000

# 4. Evaluate each clip
for clip in clip_*; do
  python -m eval evaluate "$clip" --sampling-fps 2.0
done

# 5. Generate report
python -m eval report

# 6. Read report, see decision gate
cat cv-service/eval/datasets/M5.5_EVALUATION_REPORT.md
```

**Total time**: ~2-3 hours per 5 clips (annotation is manual)

## Architecture & Philosophy

M5.5 preserves the M5 design separation:

```
PERCEPTION (M5 — validated by M5.5)
    ↓
EVIDENCE (ground-truth annotations + M5 measurements)
    ↓
INTERPRETATION (future: M6+ rally/shot detection)
    ↓
COACHING (future: AI coach reasoning)
```

**Key principles**:
- M5.5 produces **perception-level evidence only** — raw measurements, no conclusions
- No fabricated results — only measured metrics on real footage
- Licensing metadata ensures ethical data handling
- Component readiness classifications are evidence-based
- Decision gate depends on real-world accuracy, not test pass rate

---

## Limitations (Documented)

- Annotation UI is minimal but functional (accuracy > beauty)
- Per-frame court calibration not supported (single court fit per clip)
- Frame-by-frame tracking association simplified (greedy IoU matching)
- Annotation framework designed for batch processing (frame-by-frame possible, but not primary workflow)
